## 0. 项目概览

### 一句话描述(面试自我介绍用)

**中文:** 基于 Kaggle 信用卡交易数据集,处理正负样本比例 577:1 的极端不平衡分类问题。通过标准化、下采样与 SMOTE 过采样两种策略对比、K 折交叉验证选择正则化参数,以召回率为核心指标训练逻辑回归模型,最终在真实分布测试集上达到约 91% 召回率,并将误报数从 1900 降至 500。

**English:** Built a fraud detection model on the Kaggle credit card dataset with an extreme 577:1 class imbalance. Compared undersampling against SMOTE oversampling, tuned L1 regularization strength via 5-fold cross-validation optimizing for recall, and reduced false positives from ~1900 to ~500 while maintaining ~91% recall on the real-distribution test set.

### 数据集

| 字段 | 说明 |
|---|---|
| `Time` | 距首笔交易的秒数,信息量低,通常丢弃 |
| `V1` ~ `V28` | PCA 降维脱敏后的主成分,已标准化 |
| `Amount` | 交易金额,原始量级,需标准化 |
| `Class` | 标签:0 = 正常,1 = 欺诈 |

样本量:284,807 条 · 欺诈 492 条(0.172%)

### 技术栈

`pandas` · `numpy` · `matplotlib` · `scikit-learn`(StandardScaler / train_test_split / KFold / LogisticRegression / confusion_matrix / classification_report)· `imbalanced-learn`(SMOTE)

## 1. 数据认知

### 核心知识点

**为什么 V1~V28 是匿名的?**
真实信用卡交易涉及商业机密与用户隐私,原始特征无法公开。数据提供方先做 PCA 变换,发布主成分而非原始字段。

**这带来两个后果:**
1. **无法做特征工程** — 不知道每列含义,无法构造业务特征。因此本项目的价值不在特征,而在**应对不平衡的方法论**。
2. **V1~V28 已在同一量级** — PCA 前数据已标准化,主成分天然处于 0 附近的小范围;只有 `Amount` 是"漏网之鱼"。

### 面试题

**Q1.1 ⭐ 为什么这个数据集的特征是匿名的?这对建模有什么影响?**

要点:
- 隐私与商业机密,通过 PCA 变换脱敏
- 影响:无法做特征工程与特征解释,模型可解释性差
- 但不影响流程:标准化、采样、评估等环节照常
- 加分:若面试官追问,可提"这也是为什么该项目常被用作不平衡分类的教学案例,变量控制得很干净"

**Q1.2 PCA 之后的特征还需要标准化吗?**

要点:通常不需要。PCA 前一般已做标准化,输出的主成分量级一致。但 PCA 未覆盖的原始列(如 `Amount`)必须单独处理。

## 2. 样本不平衡诊断

### 核心知识点

```python
count_classes = pd.value_counts(data['Class'], sort=True).sort_index()
count_classes.plot(kind='bar')
```

结果:正常 284,315 条 vs 欺诈 492 条,比例约 **577:1**。

### ⭐⭐ Accuracy 陷阱(必考)

**"傻子模型"思想实验:** 无论输入什么,一律预测为 0(正常)。

- Accuracy = 284315 / 284807 ≈ **99.83%**
- 抓到的欺诈 = **0 个**

**结论:在极端不平衡下,accuracy 被海量多数类(TN)稀释,完全失去意义。**

### 两条解决主线

| 方向 | 做法 | 对应章节 |
|---|---|---|
| 换评估指标 | 用 recall / precision / F1 / AUC 代替 accuracy | 第 7 章 |
| 改造数据分布 | 下采样(变少)或过采样(变多) | 第 4、10 章 |

口诀:**要么让它俩一样少,要么让它俩一样多。**

### 面试题

**Q2.1 ⭐⭐ 什么是样本不平衡?为什么它是个问题?**

要点:
- 定义:各类别样本数量差异悬殊(本项目 577:1)
- 问题一:模型倾向于预测多数类,少数类召回极低
- 问题二:accuracy 失效,高分模型可能毫无价值
- 问题三:损失函数被多数类主导,梯度更新方向偏向多数类

**Q2.2 ⭐⭐ 准确率 99.8% 的模型一定好吗?**

标准回答:不一定。若数据极端不平衡,全部预测为多数类即可达到该准确率,但少数类召回为 0。应改用 recall、precision、F1 或 PR-AUC 评估。

**Q2.3 处理样本不平衡有哪些方法?(展开回答)**

| 层面 | 方法 |
|---|---|
| 数据层面 | 下采样(RandomUnderSampler)、过采样(SMOTE / ADASYN / BorderlineSMOTE)、混合采样(SMOTEENN) |
| 算法层面 | `class_weight='balanced'`、Focal Loss、代价敏感学习 |
| 评估层面 | 改用 recall / F1 / PR-AUC / MCC |
| 决策层面 | 调整判定阈值 |
| 建模思路 | 转为异常检测问题(Isolation Forest / One-Class SVM / AutoEncoder) |

> 能答出 4 个层面以上,这题基本满分。

## 3. 特征标准化

### 核心知识点

**为什么只标准化 `Amount`?**
V1~V28 已随 PCA 标准化(范围约 -3~3),`Amount` 范围 0~25691。量级差异会导致:
- 模型误判特征重要性,被大数值特征主导
- 梯度下降收敛困难,不同维度步长失衡
- 正则化惩罚不公平(惩罚项对大尺度特征的权重压制更强)

```python
from sklearn.preprocessing import StandardScaler

data['normAmount'] = StandardScaler().fit_transform(
    data['Amount'].values.reshape(-1, 1)
)
data = data.drop(['Time', 'Amount'], axis=1)
```

### ⭐⭐ reshape(-1, 1) 详解(必考)

**它只改变形状,不改变数值。**

- `1` = 要 1 列(1 个特征)
- `-1` = 行数由 numpy 自动推断

`(284807,)` 一维 → `(284807, 1)` 二维单列。

**为什么需要它?** `StandardScaler` 要求输入为二维 `(样本数, 特征数)`,而 `Series.values` 是一维,直接传入报错 `Expected 2D array, got 1D array instead`。

**常见误解:** `-1` **不是**指"压缩到 -1 到 1 之间"。数值压缩由 Scaler 完成,与 reshape 无关。

### ⭐ StandardScaler vs MinMaxScaler vs RobustScaler

| | 公式 | 输出范围 | 抗离群值 | 适用场景 |
|---|---|---|---|---|
| **StandardScaler** | (x−μ)/σ | 不固定,均值0方差1 | 中等 | 数据近似正态、有离群值、本项目 |
| **MinMaxScaler** | (x−min)/(max−min) | 严格 [0,1] | **差** | 分布均匀、边界明确、图像像素 |
| **RobustScaler** | (x−中位数)/IQR | 不固定 | **强** | 离群值多 |

**⭐ 为什么本项目不用 MinMaxScaler?**

`Amount` 最大值 25691(离群点),分母 = max−min ≈ 25691。结果:
- 25691 → 1.0
- 149.62 → 0.0058
- 绝大多数正常金额被挤压到 0~0.02 的极窄区间

**一个离群点独占 98% 的值域空间,正常样本间的区分度被抹平。** 这叫"离群点主导缩放 / 有效分辨率被压缩"。

> 注意用词:这不是"样本不平衡"。不平衡特指**类别数量**失衡;这里是**特征值缩放**失真。

**StandardScaler 后数值范围是多少?**
不固定。只保证均值 0、标准差 1。Amount 标准化后:多数值落在 -0.35~2,但最大值 25691 → 约 **102**,离群点依然是离群点。

### 面试题

**Q3.1 ⭐⭐ 为什么要做特征标准化?哪些模型需要,哪些不需要?**

要点:
- 需要:线性回归、逻辑回归、SVM、KNN、神经网络、PCA、K-Means(所有基于距离或梯度的模型)
- 不需要:决策树、随机森林、XGBoost、LightGBM(基于分裂点,对单调变换不敏感)

**Q3.2 ⭐⭐ `reshape(-1, 1)` 的 -1 是什么意思?**

见上文。回答时务必强调"改形状不改值"。

**Q3.3 ⭐⭐ 标准化应该在切分数据集之前还是之后做?**

**之后。** 必须先切分,再用**训练集**的 μ 和 σ 去 transform 测试集:

```python
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train)   # fit + transform
X_test_scaled  = scaler.transform(X_test)        # 只 transform, 不 fit
```

若先标准化再切分,测试集的统计信息泄漏进了训练过程 → **数据泄漏(data leakage)**,测试分数虚高。

> 本项目课程代码先标准化再切分,严格来说不规范,面试时可主动指出这一点,是加分项。

## 4. 下采样策略

### 核心知识点

思路:从多数类中随机抽取与少数类等量的样本,构成 1:1 数据集。

```python
number_records_fraud = len(data[data.Class == 1])       # 492
fraud_indices  = np.array(data[data.Class == 1].index)
normal_indices = data[data.Class == 0].index

random_normal_indices = np.random.choice(
    normal_indices, number_records_fraud, replace=False
)
under_sample_indices = np.concatenate([fraud_indices, random_normal_indices])
under_sample_data = data.iloc[under_sample_indices, :]
```

**`replace=False` 为什么必须?** 表示不放回抽样,保证 492 个样本互不重复。若为 `True`,同一条样本可能被抽中多次,产生重复数据。

### ⭐⭐ 下采样的代价(必考)

从 284,807 条砍到 984 条,**丢弃了 99.65% 的正常样本**。

后果:
- 模型只见过 492 个正常样本,对"正常"的认知极其狭窄
- 表现为**过度警觉**:遇到略微不寻常的正常交易就报警
- 结果:recall 高(约 0.93),但 **FP 高达 1900,precision 仅 0.06**

**关键区分:这是"数据被扔光"导致的,不是"模型没训练好",也不是"阈值没调好"。**
- 阈值是**调节旋钮**(缓解症状)
- 数据不足才是**病根**(需要 SMOTE 治本)

### 面试题

**Q4.1 ⭐ 下采样和过采样的区别?各自的优缺点?**

| | 下采样 | 过采样 |
|---|---|---|
| 做法 | 减少多数类 | 增加少数类 |
| 优点 | 训练快、内存小 | 保留全部信息 |
| 缺点 | **丢失大量信息**、误报率高 | 计算开销大、可能过拟合或引入噪声 |
| 适用 | 数据量极大、多数类冗余高 | 数据量有限、少数类信息宝贵 |

**Q4.2 ⭐ 下采样为什么会导致误报率高?**

见上文"下采样的代价"。核心答案:**模型见过的正常样本太少,对正常模式的覆盖不足,判别边界过于保守(偏向报警)。**

**Q4.3 随机下采样有什么改进方案?**

- **EasyEnsemble**:多次下采样训练多个模型再集成,避免信息丢失
- **BalanceCascade**:迭代式,每轮剔除已被正确分类的多数类样本
- **NearMiss**:按距离规则选择"最有信息量"的多数类样本,而非随机
- **TomekLinks / ENN**:清理类别边界上的噪声样本

## 5. 数据切分与交叉验证

### 核心知识点

```python
from sklearn.model_selection import train_test_split
# 旧版是 sklearn.cross_validation,已废弃

X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.3, random_state=0
)
```

**`random_state` 的作用:** 固定随机种子,保证每次切分结果一致,实验可复现。填 0 还是 42 不重要,重要的是固定。

### ⭐⭐ 本项目的核心工程判断

**切两次:**
- **下采样数据**的训练集(1:1)→ 用来**训练**
- **原始数据**的测试集(577:1)→ 用来**最终验收**

**口诀:用掰平的数据练,用真实的数据考。**

**为什么?** 真实环境中欺诈就是极少数,模型最终要在真实分布下工作。若只在 1:1 的下采样测试集上自测,分数会严重虚高(误杀十几个 vs 真实误杀 1900 个)。

### K 折交叉验证

**为什么单次切分不够?** 单次切分带有运气成分——可能恰好切出简单的测试集,分数偏高。

**K 折做法:** 将训练集平均切成 K 份,轮流让每份当验证集、其余 K−1 份当训练集,跑 K 轮,取平均分。

```python
from sklearn.model_selection import KFold

fold = KFold(n_splits=5, shuffle=False)
for train_index, val_index in fold.split(X_train_data):
    lr = LogisticRegression(C=c_param, penalty='l1', solver='liblinear')  # 每折新建
    lr.fit(X_train_data.iloc[train_index, :],
           y_train_data.iloc[train_index, :].values.ravel())
    y_pred = lr.predict(X_train_data.iloc[val_index, :].values)
```

**关键点:**
- `fold.split()` 返回的是**行号(索引)**,不是数据本身,需要用 `.iloc[]` 取数据
- **每折必须新建模型**,否则第 2 折会在第 1 折的模型上继续训练,数据串味
- `shuffle=False` 沿用课程写法;实战建议 `shuffle=True, random_state=0`

### ⭐ train_test_split 与 KFold 的关系

**不是二选一,而是配合使用:**

```
全部数据
  ├── 训练集 (70%) ──> 内部用 KFold 交叉验证 ──> 调参、选模型
  └── 测试集 (30%) ──> 锁进保险箱, 最后只用一次 ──> 最终验收
```

**测试集只用一次,交叉验证在训练集内部反复用。**

### 面试题

**Q5.1 ⭐⭐ 为什么需要交叉验证?**

要点:
- 单次切分结果有偶然性,评估不稳定
- K 折让每条数据都当过一次验证集,充分利用数据
- 取平均降低方差,评估更可靠
- 主要用途:**调超参数、选模型**,不是用来提升模型性能

**Q5.2 ⭐ K 折的 K 取多少合适?**

- 常用 5 或 10。K 越大→训练数据越多、偏差越小,但计算成本越高、方差可能增大
- 极端情况 K = n 称为留一法(LOOCV),计算昂贵,适合极小数据集
- 数据量大时用 3~5 折即可

**Q5.3 ⭐⭐ 什么是 StratifiedKFold?为什么不平衡数据要用它?**

普通 `KFold` 随机切分,极端不平衡时**某一折可能一个正样本都没有**,导致该折 recall 无法计算或为 0。

`StratifiedKFold` 保证**每折中各类别的比例与原数据一致**。

```python
from sklearn.model_selection import StratifiedKFold
fold = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
for train_idx, val_idx in fold.split(X, y):   # 注意要传 y
    ...
```

> 本项目课程用的是普通 KFold。**面试时主动指出"不平衡数据应该用 StratifiedKFold"是明显加分项。**

**Q5.4 ⭐ 什么是数据泄漏?举三个例子。**

**定义:** 训练过程中使用了本不该获得的信息(通常来自测试集或未来),导致评估结果虚高。

三个典型例子:
1. **标准化泄漏**:先对全量数据 `fit_transform` 再切分 → 测试集统计量泄漏
2. **过采样泄漏**:先 SMOTE 再切分 → 合成样本的"父样本"可能落在训练集,合成样本落在测试集
3. **时序泄漏**:用未来数据预测过去(时序数据必须按时间切分,不能随机切)

## 6. 逻辑回归与正则化

### 核心知识点:逻辑回归三步

**① 线性加权:**

```
z = w₁x₁ + w₂x₂ + ... + w₂₉x₂₉ + b
```

**② Sigmoid 映射为概率:**

```
p = 1 / (1 + e^(-z))
```

性质:z→+∞ 时 p→1,z→−∞ 时 p→0,**z=0 时 p=0.5**。

**③ 阈值判定:** p ≥ 0.5 → 判为 1,否则判为 0。

> `predict()` 返回步骤③的 0/1;`predict_proba()` 返回步骤②的概率。

### ⭐⭐ 正则化(必考)

**本质:** 在"预测准"的目标外,再加一条"权重别太大"的约束。

```
总损失 = 预测误差 + λ × 权重大小
```

**为什么有效?** 限制权重规模 → 模型不能为迁就个别训练样本而走极端 → 降低复杂度 → 防止过拟合。

### ⭐⭐ L1 vs L2(必考)

| | L1 (Lasso) | L2 (Ridge) |
|---|---|---|
| 惩罚项 | Σ\|wᵢ\| 绝对值之和 | Σwᵢ² 平方和 |
| 效果 | 部分权重**变为 0** | 权重整体**缩小但不为 0** |
| 附加价值 | **自动特征选择**,产生稀疏解 | 保留所有特征,处理共线性更稳 |
| 几何解释 | 约束区域是菱形,顶点在坐标轴上,易与损失等高线交于轴上 → 出现 0 | 约束区域是圆形,无尖角 → 不易恰好为 0 |
| 可导性 | 在 0 点不可导 | 处处可导 |

**类比:** L1 是"没用的东西直接扔掉";L2 是"每件都少带一点"。

**ElasticNet** = L1 + L2 混合,兼顾稀疏性与稳定性。

### ⭐⭐ 参数 C(必考)

sklearn 中不直接给 λ,而是给 **C = 1/λ**:

| C 值 | λ | 惩罚强度 | 模型 | 风险 |
|---|---|---|---|---|
| C 小(0.01) | 大 | **强** | 简单 | 欠拟合 |
| C 大(100) | 小 | **弱** | 复杂 | 过拟合 |

**⭐ 本项目为什么 C=0.01(最强惩罚)胜出?**
下采样后只剩 984 条数据,样本量极小,复杂模型极易过拟合。强正则化压小权重、简化模型,反而泛化更好。

**通用经验:数据越少,需要越强的正则化。**

### ⭐ solver 与 penalty 的兼容性(易错)

| solver | 支持的 penalty |
|---|---|
| `liblinear` | L1, L2 |
| `saga` | L1, L2, elasticnet, none |
| `lbfgs`(默认) | **仅 L2** |
| `newton-cg` / `sag` | 仅 L2 |

**所以 `penalty='l1'` 必须配 `solver='liblinear'` 或 `'saga'`**,否则报错。这就是代码里两者总同时出现的原因。

### 网格搜索

```python
from sklearn.model_selection import GridSearchCV

param_grid = {'C': [0.01, 0.1, 1, 10, 100], 'penalty': ['l1', 'l2']}
grid = GridSearchCV(LogisticRegression(solver='liblinear'),
                    param_grid, cv=5, scoring='recall')
grid.fit(X_train, y_train.values.ravel())

grid.best_params_    # 最优参数组合
grid.best_score_     # 对应的交叉验证平均分
grid.cv_results_     # 全部结果明细
```

**GridSearchCV 内部就是双层循环:** 外层遍历参数组合,内层做 K 折交叉验证。手写版帮你理解机制,实战用封装版。

### 面试题

**Q6.1 ⭐⭐ 逻辑回归为什么叫"回归"却做分类?**

要点:它先做线性回归得到连续值 z,再通过 Sigmoid 映射到 (0,1) 概率区间,最后用阈值离散化为类别。核心是"回归 + 阈值"。

**Q6.2 ⭐⭐ 逻辑回归的损失函数是什么?为什么不用 MSE?**

- 损失函数:**对数损失 / 交叉熵**(Log Loss / Cross-Entropy)
- 不用 MSE 的原因:Sigmoid + MSE 会导致损失函数**非凸**,存在多个局部最优;且梯度在饱和区极小,收敛慢。交叉熵配 Sigmoid 后梯度形式简洁 `(p − y)x`,凸优化,收敛快。

**Q6.3 ⭐⭐ L1 和 L2 的区别?为什么 L1 能产生稀疏解?**

见上表。稀疏性的直观解释:L1 约束区域(菱形)的**顶点位于坐标轴上**,损失函数等高线更容易与顶点相切,而顶点意味着某些坐标为 0。L2 约束区域(圆形)光滑无角,切点一般不落在轴上。

**Q6.4 ⭐ C 参数和 λ 是什么关系?调大调小分别会怎样?**

C = 1/λ。C 越小惩罚越强、模型越简单;C 越大惩罚越弱、模型越复杂。

**Q6.5 ⭐ 什么是过拟合?怎么判断?怎么解决?**

- 判断:训练集分数远高于验证集分数;学习曲线中两条线差距持续扩大
- 解决:增加数据、正则化(L1/L2/Dropout)、降低模型复杂度、早停、交叉验证、集成学习、特征选择

## 7. 评估指标选择

### ⭐⭐ 混淆矩阵四格(必背)

以**欺诈为正类**:

| 缩写 | 全称 | 含义 | 通俗 |
|---|---|---|---|
| **TP** | True Positive | 真欺诈,判为欺诈 | 抓对了 |
| **FN** | False Negative | 真欺诈,判为正常 | **漏了** |
| **FP** | False Positive | 真正常,判为欺诈 | **误杀** |
| **TN** | True Negative | 真正常,判为正常 | 放对了 |

**记忆法:第二个字母 = 模型的判断(P=说是,N=说否);第一个字母 = 判断对错(T=对,F=错)。**

### ⭐⭐ 四大指标公式(必背)

| 指标 | 公式 | 回答的问题 | 分母含义 |
|---|---|---|---|
| **Accuracy** | (TP+TN)/全部 | 总体对了多少 | 全部样本 |
| **Recall / 召回率 / TPR** | TP/(TP+FN) | **该抓的漏了没** | 所有真实正类(**横向一行**) |
| **Precision / 精确率** | TP/(TP+FP) | **抓的都对吗** | 所有预测为正类(**纵向一列**) |
| **F1** | 2PR/(P+R) | 两者的调和平均 | — |

**关键:分子都是 TP,分母不同,回答的问题就完全不同。**

### ⭐⭐ 为什么本项目盯 recall(必考)

**代价不对称:**
- 漏一笔欺诈(FN)→ 真金白银损失数千元
- 误杀一笔正常(FP)→ 打电话核实,成本极低

**所以宁可牺牲 precision,也要保住 recall。**

**但这不是通用规则,而是业务判断:**

| 场景 | 更怕哪种错误 | 优先指标 |
|---|---|---|
| 欺诈检测 / 癌症筛查 / 安检 | 漏检(FN) | **Recall** |
| 垃圾邮件过滤 / 推荐系统 / 法院定罪 | 误判(FP) | **Precision** |
| 代价相当 | — | **F1 / AUC** |

**面试标准答法:"先判断哪种错误的业务代价更高,再选指标。"**

### ⭐ 为什么 F1 用调和平均?

调和平均对"偏科"惩罚更狠。例:P=1.0, R=0.02
- 算术平均 = 0.51(看着还行)
- F1 = 2×1×0.02/1.02 ≈ **0.039**(暴露真相)

**只有两个指标都不低,F1 才高。**

### ⭐⭐ ROC-AUC vs PR-AUC(高频延伸题)

| | ROC 曲线 | PR 曲线 |
|---|---|---|
| 横轴 | FPR = FP/(FP+TN) | Recall |
| 纵轴 | TPR = Recall | Precision |
| 对不平衡的敏感度 | **不敏感**(FPR 分母含巨大的 TN,被稀释) | **敏感** |
| 适用 | 类别较均衡 | **极端不平衡(本项目)** |

**结论:极端不平衡场景应优先看 PR-AUC / Average Precision,ROC-AUC 会给出过于乐观的假象。**

```python
from sklearn.metrics import roc_auc_score, average_precision_score
roc_auc_score(y_test, y_proba)            # ROC-AUC
average_precision_score(y_test, y_proba)  # PR-AUC
```

### 代码

```python
from sklearn.metrics import (recall_score, precision_score, f1_score,
                             classification_report, confusion_matrix)

print(classification_report(y_test, y_pred))   # 一次看全部, 实战最常用
```

### 面试题

**Q7.1 ⭐⭐ 精确率和召回率的区别?能不能同时提高?**

见上文。同时提高的前提是**改进模型本身**(更好的数据/特征/算法),仅调阈值只能此消彼长。

**Q7.2 ⭐⭐ 什么时候用 recall,什么时候用 precision?**

见场景表。答题要落到"业务代价对比"。

**Q7.3 ⭐ 为什么不平衡数据用 PR 曲线比 ROC 曲线好?**

因为 FPR 的分母 (FP+TN) 中 TN 极其巨大,即使 FP 很多,FPR 依然很小,ROC 曲线看起来很漂亮但掩盖了误报问题。PR 曲线的 precision 分母是 (TP+FP),直接反映误报影响。

**Q7.4 什么是 MCC?**

马修斯相关系数(Matthews Correlation Coefficient),综合四个格子的平衡指标,取值 −1~1,在不平衡数据上比 F1 更稳健。

## 8. 混淆矩阵

### ⭐⭐ sklearn 的排布(必记,极易出错)

```python
from sklearn.metrics import confusion_matrix
cm = confusion_matrix(y_test, y_pred)
```

```
              预测=0    预测=1
真实=0     [[  TN   ,   FP  ]
真实=1      [  FN   ,   TP  ]]
```

| 索引 | 含义 |
|---|---|
| `cm[0,0]` | TN 放对了 |
| `cm[0,1]` | **FP 误杀** |
| `cm[1,0]` | **FN 漏了** |
| `cm[1,1]` | TP 抓对了 |

**行 = 真实,列 = 预测,标签升序排列(0 在前)。**

```python
recall = cm[1,1] / (cm[1,0] + cm[1,1])
precision = cm[1,1] / (cm[0,1] + cm[1,1])
```

### ⭐⭐ 核心实验结果(项目最重要的发现)

**同一个下采样模型,在两个测试集上的表现:**

| | 下采样测试集(1:1,约296条) | 原始测试集(577:1,85443条) |
|---|---|---|
| Recall | ≈ 0.93 | ≈ 0.93 |
| FP 误杀 | 约 3~15 个 | **约 1900 个** |
| Precision | ≈ 0.90 | **≈ 0.06** |

### ⭐⭐ 基数效应(高质量答案的关键)

**误杀率其实没变(约 2%),变的是基数:**
- 下采样测试集正常样本 ≈ 148 个 → 2% × 148 ≈ **3 个误杀**
- 原始测试集正常样本 = 85,307 个 → 2% × 85307 ≈ **1900 个误杀**

**同样的错误率,乘以 577 倍的基数,绝对数量爆炸,precision 被彻底摧毁。**

**结论:在极端不平衡下,即使很低的假阳性率,也会因多数类基数巨大而毁掉 precision。**

### 精确率 0.06 = 模型没用吗?

**不一定,取决于成本核算:**
- 人工复核 1 笔成本 10 元 × 1900 = 1.9 万元
- 每笔欺诈平均损失 3000 元,少漏 9 笔 = 省 2.7 万元

**模型好坏看业务净收益,不看指标是否漂亮。**

**Q8.1 ⭐⭐ 画出混淆矩阵并解释四个格子。**

务必按 sklearn 的排布画(TN FP / FN TP),并能从中推出 recall 和 precision。

**Q8.2 ⭐⭐ 同一个模型为什么在两个测试集上 precision 差 15 倍?**

标准答案:**基数效应**。见上文。这题能答到"错误率不变、基数放大"的层次,面试官会明显高看一眼。

**Q8.3 ⭐ 误报太多的根源是什么?**

**不是"模型没训练好",也不是"阈值没调好"。** 根源是下采样丢弃了 99.65% 的正常样本,模型对正常模式的覆盖严重不足,判别边界过度偏向报警。

**区分症状与病根:阈值是缓解症状的旋钮,数据不足才是病根。**

## 9. 阈值调节

### 核心知识点

**0.5 不是数学规律,只是默认值。**

```python
y_pred_proba = lr.predict_proba(X_test)     # (n, 2) 二维数组
y_pred = y_pred_proba[:, 1] > 0.3           # 自定义阈值, 返回布尔数组
```

### ⭐⭐ predict_proba 返回结构(必考)

| 属性 | 值 |
|---|---|
| 类型 | `numpy.ndarray` |
| 形状 | `(样本数, 类别数)`,二分类为 `(n, 2)` |
| 第 0 列 | P(属于类别 0) |
| 第 1 列 | P(属于类别 1) — **我们要的** |
| 每行之和 | **恒等于 1** |
| 列顺序 | 由 `lr.classes_` 决定,按标签升序 |

实测输出示例:

```
[[0.379217 0.620783]     ← 38% 正常, 62% 欺诈
 [0.831445 0.168555]
 [0.852221 0.147779]]
```

**`predict()` 等价于 `predict_proba()[:,1] > 0.5`** — 可用 `np.array_equal()` 验证,两者完全一致。

### ⭐ 向量化比较

```python
p = y_pred_proba[:, 1]        # [0.02, 0.87, 0.31, 0.95]
result = p > 0.5              # [False, True, False, True]
```

`>` 作用于 numpy 数组是**逐元素比较**(broadcasting 广播机制),返回等长布尔数组,不需要写循环。

**布尔数组可直接当 0/1 标签用**(Python 中 True==1, False==0),所以能直接传给 `confusion_matrix`。

```python
result.sum()   # 统计 True 的个数 = 报警总数
```

### ⭐⭐ 滑动 vs 抬升(核心洞察)

| | 调阈值 | 换模型/改数据 |
|---|---|---|
| 效果 | 在**同一条 PR 曲线上滑动** | 整条曲线**向右上方移动** |
| 结果 | recall↑ 必然 precision↓,零和 | **两者可同时提升** |
| 本质 | 换个读数方式 | 提升模型能力本身 |

**判断法则:当你发现怎么调参都是"按下葫芦浮起瓢",说明已经在曲线上了,该换的是模型或数据,不是参数。**

**如何抬升曲线:**
1. 更好的数据(SMOTE 保留全部正常样本)
2. 更强的模型(随机森林 / XGBoost)
3. 更好的特征(本项目做不到)

### ⭐ 阈值选择的规范做法

**阈值也是超参数,不能在测试集上挑!**

正确流程:在验证集或交叉验证中选定阈值 → 在测试集上验收一次。
若在测试集上试 9 个阈值再挑最好的,等于"看着答案挑答案",分数虚高。

**业务化的定法(比"F1 最高"更实用):**
- 定 recall 底线(如必须 ≥0.95),在满足条件的阈值中选 precision 最高的
- 定报警量上限(如风控团队每天最多复核 200 笔),反推阈值

### 面试题

**Q9.1 ⭐⭐ 分类阈值一定是 0.5 吗?为什么可以调?**

不一定。0.5 只是默认值。逻辑回归输出的是连续概率,阈值是人为设定的决策边界,可根据业务对 FN/FP 代价的权衡自由调整。

**Q9.2 ⭐⭐ 调低阈值会发生什么?**

更容易判为正类 → TP↑ FP↑ FN↓ → **recall 升高,precision 降低**,报警总数增加。

**Q9.3 ⭐ predict 和 predict_proba 的区别?**

`predict` 返回离散类别标签(内部按 0.5 阈值);`predict_proba` 返回各类别概率的二维数组。需要自定义阈值、排序、计算 AUC 时必须用后者。

**Q9.4 ⭐ 只靠调阈值能同时提高 precision 和 recall 吗?**

不能。阈值只能在既有的 PR 曲线上滑动,是零和权衡。要同时提升必须改进模型本身(数据、特征、算法)。

## 10. SMOTE 过采样

### 核心知识点

**SMOTE = Synthetic Minority Over-sampling Technique(合成少数类过采样技术)**

**为什么不能简单复制?** 复制 577 遍,模型看到的还是那 492 个点,只会加深记忆导致过拟合,没有引入任何新信息。

**⭐⭐ SMOTE 算法步骤(必背):**

1. 从少数类中选一个样本 **A**
2. 用 KNN 找出 A 在**少数类内部**的 K 个最近邻(默认 K=5)
3. 从 K 个邻居中随机选一个 **B**
4. 在 A 与 B 的**连线上随机取一点**作为新样本

```
新样本 = A + rand(0,1) × (B − A)
```

**本质:线性插值。** 新点落在真实少数类样本之间的区域,是"像但不同"的样本,不是复制品。

### 代码

```python
from imblearn.over_sampling import SMOTE

oversampler = SMOTE(random_state=0)
os_X, os_y = oversampler.fit_resample(X_train, y_train.values.ravel())
```

**注意:**
- 新版 API 是 `fit_resample`,旧版 `fit_sample` 已废弃
- 安装名 `imbalanced-learn`,导入名 `imblearn`(常见拼写错误:`imbalance-learn` ❌)

### ⭐⭐ SMOTE 最重要的坑(必考)

**SMOTE 只能用于训练集,绝不能用于测试集,也不能先 SMOTE 再切分。**

正确顺序:
```
切分 → 只对训练集 SMOTE → 测试集保持原始分布
```

**为什么?** 若先 SMOTE 再切分,某个合成样本由 A、B 插值而来,可能出现 A 在训练集、合成样本在测试集的情况 → 模型变相"见过"测试集 → **数据泄漏**,测试分数虚高但上线失效。

**交叉验证中,SMOTE 必须在每一折内部执行:**

```python
from imblearn.pipeline import Pipeline

pipe = Pipeline([('smote', SMOTE(random_state=0)),
                 ('lr', LogisticRegression(solver='liblinear'))])
# 交叉验证时 SMOTE 只在每折的训练部分执行, 自动避免泄漏
```

**通用纪律:任何"从数据中学习参数"的操作(标准化、SMOTE、特征选择、缺失值填充),都只能在训练集上 fit,测试集只能被动 transform。**

### ⭐⭐ 最终对比(结论必记)

同一个原始测试集上:

| | 下采样 | SMOTE |
|---|---|---|
| 训练样本数 | 984 | ≈ 398,038 |
| Recall | ≈ 0.93 | ≈ 0.91 |
| FP 误杀 | ≈ 1900 | **≈ 500** |
| Precision | ≈ 0.06 | **≈ 0.20** |

**解读:recall 几乎无损(少抓约 2 个),误杀降低近 4 倍,precision 提升 3 倍多。**

**这就是"抬升曲线"的实证** — 不是在曲线上滑动(那样 recall 必然大跌),而是整条曲线右上移。

**原因:** SMOTE 保留了全部 19 万训练用正常样本,模型对"正常"的认知充分,不再过度警觉。**病根是"数据被扔光",解法就是"别扔"。**

### SMOTE 的局限

- **边界噪声**:若两个少数类样本之间夹着多数类样本,插值可能生成落在多数类区域的"假正样本"
- **计算开销**:样本量从 984 涨到 39 万,训练明显变慢
- **高维失效**:高维空间中"最近邻"意义减弱(维度灾难)

**改进变体:**

| 变体 | 改进点 |
|---|---|
| **BorderlineSMOTE** | 只对**边界附近**的少数类样本做插值,边界最有信息量 |
| **ADASYN** | 对**更难分类**的样本生成更多合成样本,自适应分配 |
| **SMOTEENN / SMOTETomek** | 过采样后再用 ENN/Tomek 清理噪声,组合策略 |
| **KMeans-SMOTE** | 先聚类再在簇内插值,避免跨簇生成 |

### 面试题

**Q10.1 ⭐⭐ SMOTE 的原理是什么?**

见"算法步骤"。回答要点:KNN 找邻居 + 连线上线性插值,而非简单复制。

**Q10.2 ⭐⭐ SMOTE 应该在切分数据前还是后做?为什么?**

**切分之后,且只对训练集做。** 否则造成数据泄漏。交叉验证中要用 `imblearn.pipeline.Pipeline` 保证每折内部执行。

**这题是 SMOTE 相关最高频的考点。**

**Q10.3 ⭐ SMOTE 相比随机过采样(简单复制)好在哪?**

随机复制不引入新信息,极易过拟合(模型死记那几个点);SMOTE 通过插值生成新样本,扩展了少数类的决策区域,泛化性更好。

**Q10.4 ⭐ SMOTE 有什么缺点?怎么改进?**

见"局限"与"改进变体"表。

**Q10.5 除了采样,还有什么处理不平衡的办法?**

- `class_weight='balanced'` — 在损失函数中给少数类更大权重,无需改动数据
- 代价敏感学习 / Focal Loss
- 阈值调整
- 异常检测建模(Isolation Forest、One-Class SVM、AutoEncoder)
- 集成方法(BalancedRandomForest、EasyEnsemble)

| `arr[:, 1]` | numpy 二维数组的第 1 列(降为一维) |

### 布尔索引

```python
data[data.Class == 1]                      # 筛选行
data[data.Amount > 1000]                   # 条件筛选
df.iloc[:, df.columns != 'Class']          # 排除某列
(p > 0.3) & (p < 0.7)                      # 逐元素与, 注意用 & 不是 and
```

### iloc vs loc

| | 依据 | 示例 |
|---|---|---|
| `.iloc[]` | **位置**(整数) | `df.iloc[:, 0]` |
| `.loc[]` | **标签**(名称) | `df.loc[:, 'Amount']` |

### 形状变换

| 操作 | 作用 | 形状变化 |
|---|---|---|
| `.reshape(-1, 1)` | 一维立成一列 | `(n,)` → `(n,1)` |
| `.reshape(1, -1)` | 一维躺成一行 | `(n,)` → `(1,n)` |
| `.ravel()` | 抻平为一维(**返回视图**) | `(n,1)` → `(n,)` |
| `.flatten()` | 抻平为一维(**返回拷贝**) | `(n,1)` → `(n,)` |
| `.reshape(-1)` | 抻平为一维 | 同上 |

**⭐ `reshape(-1,1)` 与 `ravel()` 互为逆操作:**
- 喂给 `StandardScaler` 的 X → 需要 `reshape(-1,1)` 变二维
- 喂给 `fit()` 的 y → 需要 `.ravel()` 变一维

## 附录 B: 常见错误排查

| 报错 | 原因 | 解决 |
|---|---|---|
| `Expected 2D array, got 1D array` | 一维数组传给要求二维的 API | `.reshape(-1, 1)` |
| `Found input variables with inconsistent numbers of samples: [85443, 137]` | y_true 与 y_pred 长度不符,通常是 Jupyter 中残留的旧变量 | 重新 predict 生成配对的 y_pred;或 Restart Kernel & Run All |
| `NameError: name 'X_train_data' is not defined` | 变量未定义或名称不一致 | 检查上游 cell 是否执行、for 循环接收名与使用名是否统一 |
| `DataConversionWarning: A column-vector y was passed` | y 是 (n,1) 二维 | `.values.ravel()` |
| `ValueError: Solver lbfgs supports only 'l2' penalty` | solver 与 penalty 不兼容 | 用 `solver='liblinear'` 或 `'saga'` |
| `ModuleNotFoundError: No module named 'imblearn'` | 未安装或装错环境 | `%pip install imbalanced-learn` 后重启 kernel |
| `Could not find a version that satisfies imbalance-learn` | 包名拼写错误 | 正确名是 `imbalanced-learn`(带 d) |
| `AttributeError: 'SMOTE' object has no attribute 'fit_sample'` | 旧版 API | 改用 `fit_resample` |
| `ImportError: cannot import name from sklearn.cross_validation` | 模块已废弃 | 改为 `sklearn.model_selection` |

### ⭐ Jupyter 使用纪律

1. 用 `%pip install`(带百分号)而非 `pip install`,保证装进当前 kernel 环境
2. 改完代码 **Restart Kernel & Run All**,避免内存中残留的过时变量造成"静默错误"
3. 变量全局共享,for 循环结束后循环变量仍保留最后一次的值 — 这是长度不匹配报错的常见来源

### 新旧 API 对照

## 附录 E: 项目复盘话术(面试常问)

**Q: 这个项目最大的挑战是什么?**

样本极端不平衡(577:1)。直接建模会导致模型全部预测为正常类,虽然准确率 99.8% 但召回为 0,毫无业务价值。

**Q: 你是怎么解决的?**

分三层:评估层改用 recall 为核心指标;数据层对比了下采样与 SMOTE 两种策略;决策层通过阈值调节做精细权衡。最终 SMOTE 方案在保持约 91% 召回的同时,将误报从 1900 降至 500。

**Q: 如果重做这个项目,你会做什么改进?**

1. 改用 `StratifiedKFold`,保证每折类别比例一致
2. 标准化放在切分之后,用 Pipeline 封装避免数据泄漏
3. 补充 PR-AUC 作为主评估指标,ROC-AUC 在此场景过于乐观
4. 尝试 XGBoost + `scale_pos_weight`,以及 BorderlineSMOTE
5. 对阈值做业务化定义(如约束日均复核量),而非单纯优化 F1

**Q: 模型上线后你会监控什么?**

召回率与误报量的实际业务反馈、特征分布漂移(data drift)、欺诈模式变化导致的概念漂移(concept drift),并设置定期重训机制。
